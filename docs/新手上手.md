# TagViewer 新手上手

> 环境怎么搭、数据放哪、五步走通第一条链路。
> 先看视频？[tutorial-video/out/tagviewer-tutorial.mp4](../tutorial-video/out/tagviewer-tutorial.mp4)（约 2 分钟，带配音讲解）。
> 这里只写「不随版本变的东西」，细节和原理一律链接到 [README](../README.md) 对应章节 ——
> 两边万一冲突，以 README 为准。

## 这个应用是干什么的

**把图片变成 tag 的「弹药库」，让 ComfyUI 抽卡越抽越自由。**
它给本机图片库自动打标（WD14 反推）、按「作品 → 角色」归类、筛选浏览，
最后把选好的标签组合导出成角色组文件，直接喂给 ComfyUI。
全程本地运行，不上传任何数据。

先认识三个核心概念：

| 概念 | 是什么 |
|---|---|
| **来源** | 登记进看板的图片文件夹。看板上能搜到的图都来自「来源」 |
| **反推（WD14）** | AI「看图说话」：给没有标签的图自动生成一套标签 |
| **购物车** | 把喜欢的角色攒成一支队伍，一键导出成一个角色组文件 |

## 一、装环境

**拿到了绿色分发包（`TagViewer-点击即用包-v*.zip`）的人，本节可以整段跳过** ——
解压到任意可写目录，双击「启动看板.bat」就能用，什么都不用装。
中文标签、WD14 打标模型和反推用的 Python 环境**都已内置**；你的数据默认也存在
包内的 `data\` 文件夹里，换电脑把整个文件夹拷走即可，卸载 = 删文件夹。

> 分发包有三种：
> **点击即用包**（全带，解压即用，什么都不用弄）、
> **基础包**（不带 1.27GB 模型，反推环境一样带 —— 按包内「使用说明.txt」下两个模型文件
> 放进 `models\` 就齐了）、
> **精简包**（模型和 Python 环境都不带，体积最小，适合传网上分发给会自己配环境的人 ——
> 自己装 Python + `pip install onnxruntime`，再按下述说明下模型）。
> 基础包用户只有「模型下载」那一步要做，其余本节也可跳过。

**从源码跑**才需要：**Windows** + **Node.js**（≥ 20.19，Vite 7 的底线；npm 随 Node 一起装）。

```bat
git clone / 解压本项目后，在项目根目录：

npm install        :: 自动复用本机已有的 Electron 运行时，找不到才官方下载（100+MB）
npm run build      :: 构建前端到 dist/
npm start          :: 启动。以后日常用直接双击「启动看板.bat」（.vbs 不弹黑框）
```

要改前端代码做开发时用 `npm run dev`（Vite 热更新，不用反复 build）。

### 可选：装 WD14 反推（不装也能用）

反推需要三样东西，**缺任何一样应用都会自动降级** —— 其余功能一个不少，
只是扫描页不能给裸图打标：

| 要什么 | 绿色包用户（点击即用包 / 基础包） | 精简包用户 / 从源码跑的用户 |
|---|---|---|
| Python 3 + onnxruntime | **包内已带**（`python\` 文件夹），什么都不用装 | 需要自己装（见下） |
| 模型（1.27GB） | 点击即用包**已内置**；基础包需要自己下载（见下方说明） | 需要自己下载（见下方说明） |

**Python 3**：[python.org](https://www.python.org/downloads/) 下载装到 PATH，
或装 miniconda / anaconda（应用会自动在这几处找 Python）。

**onnxruntime**：命令行执行 `pip install onnxruntime`（国内慢可加
`-i https://pypi.tuna.tsinghua.edu.cn/simple`；CPU 版就能跑只是慢些，
有 N 卡想跑 CUDA 就装 `onnxruntime-gpu`）。

**模型下载（只针对基础包用户 / 从源码跑的人）**：用的是 PixAI 官方 tagger 的 ONNX 导出版，
来自 HuggingFace 仓库
[deepghs/pixai-tagger-v0.9-onnx](https://huggingface.co/deepghs/pixai-tagger-v0.9-onnx)：

1. 下载仓库里的两个文件：**`model.onnx`** 和 **`selected_tags.csv`**。
   国内直连 `huggingface.co` 大概率超时，把域名换成镜像站即可：
   <https://hf-mirror.com/deepghs/pixai-tagger-v0.9-onnx>；
2. 在**项目根目录**新建 `models/` 文件夹，把两个文件**原名放进去就行，不用改名**
   （也支持放在数据目录下的 `models/`；改名版 `wd-pixai-tagger-v0.9.onnx/.csv`
   一样认，两种名字同时存在时认改名版）：

   ```text
   models/
   ├─ model.onnx         （或 wd-pixai-tagger-v0.9.onnx）
   └─ selected_tags.csv  （或 wd-pixai-tagger-v0.9.csv）
   ```

环境不全的时候不用翻文档 —— 打开**扫描页**会有一条「看看怎么装」的常驻引导，
点开就是上面这几步和下载地址。放好后重启应用即生效；到底找没找到，
`launch.log` 里反推那行会说实话。

不想让它跑：环境变量 `TV_TAGGER=0` 一句话关闭。Python/模型在非标准位置的更多
配置见 `electron/core/tagger.js` 头部注释。

## 二、放数据（第一次打开）

**绿色包用户**：第一次启动会直接请你「📁 选择图片文件夹」—— 点按钮选一个
装满图的目录，登记后自动扫描入库，这就开始了，不用碰任何文件。
数据默认存在包内 `data\` 文件夹。

**从源码跑的用户**：仓库里同样一个数据文件都没有。第一次启动的引导页上
也是同一个「选择图片文件夹」按钮，用法完全一样；也可以顶栏 →「🗄️ 来源」
→「添加文件夹」。登记即扫描入库；`auto_tag` 默认开，没有标签的图会自动
排上 WD14 反推。

到这一步应用就完整可用了，下面是一节可选的升级和一处你要知道的路径。

### 中文翻译：开箱即有（可选升级）

中文标签来自 **WeiLin 的 ComfyUI 标签翻译库**（就是 ComfyUI 插件
[WeiLin-Comfyui-Tools](https://github.com/weilin9999/WeiLin-Comfyui-Tools) 用的那套
`userdatas_zh_CN_*.db`）。这份库已**随仓库/包内置**（`knowledge/` 目录，来源与授权
说明见 [knowledge/README.md](../knowledge/README.md)）—— 装好就有中文，什么都不用做。

想更进一步的话：

| 你手里有什么 | 怎么做 | 效果 |
|---|---|---|
| 更新/别版的 `weilin_data(...)` 翻译库 | 整个文件夹丢进**数据目录**（名字保持 `weilin_data` 开头） | 优先用你的那份，盖过内置库 |
| 自己整理的一些翻译 | 写进数据目录的 `local_translations.json`（格式 `{"英文标签": "中文"}`） | 补在翻译库没有的词条上 |
| 都没有 | 什么都不用做 | 内置库兜底；万一连内置也没有，只显示英文，不会崩 |

翻译库每次启动加载成没成功，`launch.log` 里都有一行实账（`来源=仓库内置` /
`来源=数据目录自动发现`）。

### 数据目录在哪

**绿色包**：就在包内的 `data\` 文件夹（数据随包走，换电脑拷整个文件夹）。
从源码跑：菜单里「打开数据目录」可以直接跳过去；与项目同目录的 `data/`
存在就用它，否则是 `%APPDATA%\TagViewer\data`。想显式换位置
（settings.json / `TV_DATA_DIR`）以及里面各类文件的分类说明，
见 README「路径与数据目录」。

## 三、走通第一条链路（五步）

| 步 | 去哪 | 干什么 |
|---|---|---|
| **1. 登记来源** | 顶栏 → 🗄️ 来源 | 「添加文件夹」选一个装满图的目录，登记即扫描入库，裸图自动排上反推 |
| **2. 看板筛图** | 看板（Home） | 筛选框按标签/角色搜图（认中文）；点来源胶囊只看某个文件夹；安全模式一键藏敏感图 |
| **3. 光箱看图** | 点开任意一张 | 全屏翻页；快速移动条的数字键 1~9 把当前图一键移进常用文件夹归档 |
| **4. 攒购物车** | 系列页 / 详情页 | 按「作品 → 角色」浏览，看中的角色点 🛒 入车；想画双人图就把两个角色都丢进去 |
| **5. 导出去抽卡** | 购物车 / 首页动作区 | 购物车一键结算导出角色组；导出预设可以 ban 掉不要的词（比如 `closed_eyes`）、配自动导出。导出的文件扔进 ComfyUI 直接抽卡 |

玩熟之后的进阶玩法 —— 扫描页批量打标与排序、标签页直接 ban、收藏页 + 备注、
导出替换/背景补全规则、5 套主题 —— 都在 README「功能一览」表里，每个一行的导航。

## 四、出问题看哪

先看日志：开发期是项目内 `logs/launch.log`。启动流程、翻译库加载、反推探活
都会在这里各留一行，`[warn]` 开头的就是要找的。

| 症状 | 大概率是 | 怎么办 |
|---|---|---|
| 界面标签全是英文 | 翻译库没加载上（内置库被移走/损坏） | 看 launch.log 里的 `翻译库:` 那行实账；也可以放一份自己的 `weilin_data*` 进数据目录（见「二」） |
| 看板是空的 | 没登记来源，或来源被「移出」了 | 来源页看一眼：移出 ≠ 删除，文件没动，开关打回来就恢复 |
| 卡片缩略图 404 | 文件在应用外被移动/改名了 | 跑一次增量同步（`npm run ingest`）把陈旧记录标成 gone |
| 扫描页不能给裸图打标 | WD14 反推降级了 | Python / onnxruntime / 模型三样缺一都降级；扫描页的「看看怎么装」引导条 + launch.log 看 probe 那行 |
| 双击启动没窗口 | 窗口没真正起来 | 看项目内 `logs/ready.flag` 有没有生成 |

更多诊断命令（`db:info` / `db:verify` / `smoke` / `search:check` …）见 README
开头的命令表；真觉得坏了想回滚，直接用旧版 `../tag_viewer/` 的启动脚本
（README「与旧版共存 / 回滚」）。
