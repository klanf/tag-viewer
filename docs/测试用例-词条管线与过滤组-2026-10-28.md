## 〇、澄清问题清单（执行前确认，不臆造）

1. **待确认**：变体输出无角色词，与购物车 wildcard（有角色词）如何拼装（wildcard 引用？逐行拼接？）——需求未定，B5 相关用例只验证到「剥离干净」为止。
2. **待确认**：`--n` 与 `--file` 行数叠加时的总量上限是否需要保护（当前无上限，1 万行×100 变体=100 万次抽签）——性能用例按「单文件 ≤1 万行」假设设计。
3. **待确认**：过滤组 keepOne 的「胜者=本地图片量最多」是否符合用户预期，还是应保留原型词（变体重抽场景与复制场景语义不同）。

## 一、测试范围与策略概述

被测功能四条链路 + 一个引擎：

| 模块 | 入口 | 核心逻辑 |
|---|---|---|
| M1 光箱复制 | 光箱复制面板「过滤组去冲突」开关 | `filterTagsLikeExport(opts.groups)` |
| M2 购物车导出 | 结算弹窗「过滤组去冲突(附加标签)」 | `buildCartExport(groups)` + forceSolo，角色主标签永不剔 |
| M3 批量导出 | 看板导出菜单「过滤组去冲突」开关（**本次修复 A1**） | `buildExport(raw.groups)` |
| M4 预设自动导出 | 预设编辑「过滤组去冲突」+ ban 后自动导出（**本次修复 A1**） | `toExportQuery` groups 透传 → `buildExportAsync` |
| M5 变体引擎 | `scripts/variant-prompt.mjs` CLI | 角色剥离→本体锁定→可变槽抽签（反比软降权）→过滤组→排序（**本次修复 A3**） |

策略：M1–M4 的过滤组核心是同一组纯函数（`applyFilterGroups` + `groupsCtx`），采用**判定表**设计用例后，在每条链路上各跑一遍集成冒烟（同一输入不同出口）；M5 采用**等价类+边界值+错误推测**。纯 Node 可自动复跑的用例标注 ✅；依赖 Electron UI 的手工用例标注 🖱（步骤已给出，待执行）。
